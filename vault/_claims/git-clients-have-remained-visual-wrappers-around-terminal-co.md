# git clients have remained visual wrappers around terminal commands, and developers suffer tab-switching fatigue jumping between code, history and the terminal

Asserted by [[gitcanopy]] — *GitCanopy*  
<sub>Frostbyte Hackathon</sub>

**Problem** the tool for reasoning about change is a front end for typing commands, so the reasoning happens in the developer's head across three windows

**Mechanism** a client designed around architectural clarity and continuous rendering  
**Beneficiary** developer navigating history
