# an on-chain backend gives verifiable shared state and a game engine gives the experience, so the design problem is joining two systems with opposite latency assumptions

Asserted by [[hexploration]] — *Hexploration*  
<sub>Chainlink Spring 2022 Hackathon</sub>

**Problem** on-chain games look poor and engine games have no verifiable shared state

**Mechanism** an engine frontend over on-chain state with verifiable randomness and scheduled progression  
**Beneficiary** players wanting both quality and verifiable ownership
