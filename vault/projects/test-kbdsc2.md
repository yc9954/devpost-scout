## Body

Crime Report Information Police Comms System Genai Databases Digital Sketch Artist Inspiration I always wanted to experience what it's like to solve cases and being the one who drives it forward. Much like the mechanics of games like L.A. Noire, Detroit: Become Human and ones from Telltale fascinated me how the game story changes on what the player chooses at a point in time. But after completing the main storyline there seemed to be no objective for me to play the game again. As these games rely heavily on their story, it felt redundant to play all over again just to see different endings. What if there was a game that didn't have a main storyline? Real-life detectives don't have one, and that's what makes it unpredictable and feel at a higher stake. What if we could bring this dynamic into a game and make it a truly unique experience for the player? Presenting, Parable Rhythm. An interactive crime thriller RPG that provides you a unique experience of solving cases and driving the story forward. Every action, every approach will truly result in an unexpected pattern of events. What it does Set in the modern town of Genai (pronounced gun-aa-ee), you play as a newbie detective who has been assigned a desk job at the headquarters. The Police Department assigns cases for you, to solve them through their software. Your task is to communicate and collaborate with the lead in-charge of cases, Inspector Neel Ray to catch the culprit(s). This "software" is essentially the game. You are provided with many widgets that ensure you succeed in your journey. Let's go through a general flow of the game. (Just an example for widget introduction, you may get a totally different story) You receive a short crime report and a crime scene photograph. After reading this, you start your chat with Inspector Ray through the Genai PD Comms. System. Ask for detailed crime report, witness statements, CCTV/traffic cam footages, initiate door-to-door interrogations; basically anything you could achieve in real life investigation. Suppose Ray got a hit on a license plate through a CCTV cam, here you get to use the Genai Database Access Terminals. There are 3, mainly used for - Residents Info, Car Registration Registry, Criminal Registry. Yep you got it. We run a search of the license plate in the Car Registration Registry and get the owner name/id. Then run through the Resident Info Access Terminal to get the address, contact no., etc. Also cross-check if there are any past criminal charges this resident had. Pass this data onto Ray to interrogate the suspect. After reading the transcripts of this interrogation, if you think the suspect is the culprit we convey this to Ray. The story can go either ways from here. Other than the entertainment aspect, the game helps in building analytical thinking and an increase in attention to detail as these are the key aspects around solving cases in the first place. How it was built So how does it exactly create this dynamic? How do we exactly build a system that analyses player inputs and reacts accordingly while referencing other aspects on data (eg. crime report, Genai Database Access Terminals, etc.) and driving the story further? Using the power of Generative AI, we could achieve everything. The random Genai Database generations, a chatbot to enact Inspector Ray and an image generator for the crime scene photograph. Setting up a backend and the infra to handle all of these services from scratch is definitely not a piece of cake. Thanks to PartyRock, creating AI apps powered by Generative AI has never been easier. The pre-configured LLMs and frontend infra, provides us with widgets that can be used for taking in user input, create chatbots, text generators and image generators; all configured in such a way that we can reference these widgets to share data between them. This powerful Amazon Bedrock playground enables low/no-code AI app creation in a matter of seconds! Challenges I ran into One of the first challenges I faced was of not receiving accurate data outputs from the LLM. Had to iterate multiple times, testing out different prompting methods, giving output examples to make the LLM give accurate results. While making prompts, Claude would hallucinate a lot of stuff. Making the Inspector Ray chatbot to collaborate with the user and also carry forward the story was a significant challenge, also the first time I wrote several paragraphs for an AI prompt. After building all the widgets, I noticed a significant lag and sometimes bound to errors when multiple widgets were getting generated where the user had to manually restart the generation. That was bad UX, so I configured the widgets to run sequentially to reduce the load. Although the load times are longer, but bearable and happens behind the scenes as you read the game instructions. Among other challenges, one was keeping up with updates to PartyRock. While building and testing the game, I came across some updates to widget behaviors that broke the flow of the game. Two major breaking changes were, No automating generation of Text Gen widget : The game was designed in a way so that the underlying databases would start generating as soon as the user accesses the game page. So that while the user is reading game instructions and character bio, the game initializes all the elements and gets ready to play. But after the change, the Master Database text gen widget would no longer generate text automatically as soon as the user accesses the page. It had to have another widget as its dependency to start. I decided to add a text input where the user types in "Start" to start the text generation. Text Gen widget lag : One of the major breaking change. The game was working smoothly, with sequential widget loading implemented. But after this change, it caused even the sequential loading to stutter and lag. Even though there were 1 or 2 widgets generating concurrently, the stutter had become unbearable. Tried changing LLMs, prompts, limiting the response a bit more. Unfortunately, for a better UX I had to remove the Master Database (among 3 Genai databases) from the text gen widget and make it static. This was the only way to make the loading times, well, bearable. It seems like a regression issue, which does seem to make the text streaming from LLM too heavy or the way other widgets act with their "dependency" widgets. One issue I came across was of an exceeded limit of character input. Basically an error where the input token context window of Claude Instant had exhausted after the Inspector Ray chat widget had become too long upto a point where this error is thrown and the game is interrupted. Using the larger Claude model that has a larger context doesn't make sense in the chatbot as it takes a lot of time to generate and is an overkill. Accomplishments that I'm proud of The journey building Parable Rhythm taught me quite a lot of things. A great experience to have nevertheless in the hackathon. One of the major things I learnt through the process is having become a better prompt engineer. Knowing what and how to prompt has become an essential skill in daily life, and really helps in getting tasks done faster. It helped me to produce accurate and concise results so that Parable Rhythm uses less credits and enables more replay-ability! Making such a game with a lot of moving parts was definitely a challenge for me to make the player understand and not be overwhelmed by it. I'm happy the UI placement flexibility and static texts worked well hand in hand to provide a better user experience. In addition, I wanted the introductory video of Parable Rhythm to be different, of course while still explaining the app and make the audience understand what it is about. I thought, as it is a game, why not make the video like an actual trailer? Well, it would be engaging, would explain the game/app by giving a (sort of) walk-through and pique curiosity in the viewer to play the game. Through some ups and downs, I got the chance to team up with some of friends to have the video shot. It was an exhilarating experience, having shot my first public short film? You can view the trailer here. Exactly like a real world scenario, not all things go as planned. The initial game breaking changes to PartyRock actually made me implement a real world scenario where not everything should be generated by A.I in realtime just because it can . Making the A.I generated Master Database to Static Master indeed proved that the user experience should be a higher priority than using cutting-edge tech wherever possible; when that simply should not be the case. Having got a chance to share my learning and thoughts about building a real world scenario and cloud architectures through writing a technical blog on community.aws was a delightful experience. What I learned I discovered many LLMs to choose from when creating the app, they all produced different outputs even though the prompt was the same. It made me wonder, when and how would I use these models? Upon researching, I had found a great resource that explained how every model on Amazon Bedrock is used for a different usecases/scenarios. Helped me dive deep into the plethora of models that Bedrock provides along with the newly added ones like Mistral and Claude 3. This was the first time I learnt that even Amazon has their own LLM, Titan. Though haven't tried the Image Gen on Titan (not available on PartyRock), would definitely be excited to! Architecting a game/app, infrastructure on the AWS cloud was both filled with knowledgeable insights and a ton of fun. Imagining real world scenarios of the app actually opened up possibilities for me to pursue and build an actual game with all these doors open to amazing tech. What's next for Parable Rhythm Though being a prototype of a grand scheme, it taught a lot of things that need to be iterated upon to truly make it a great game. Missing elements like graphics, more accessible and playable content is still a part that makes a game complete. The blueprint (the blog) is ready, underlying tech is ready (thanks to the cloud), now all that remains is me getting ready with a design spec and a team to build the next-gen gaming experience soon. A fully dynamic, AI powered game mechanic that completely immerses the player giving them a unique experience. <div
