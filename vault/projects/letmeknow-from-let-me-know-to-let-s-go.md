Save the verdict as a shareable card and drop it back in the chat Novus Dashboard - Backend Novus Dashboard - Frontend Inspiration Every friend group has the same broken ritual. Someone asks "what do you want to do?" and the chat goes quiet. Forty-five minutes later — "idk, what do you want to do?" — still nothing. We kept living it: the message that's been "seen" for two hours, the plan that never lands, the night that almost didn't happen. And we realized the problem was never a lack of options . It's that nobody wants to be the one who decides, everyone's holding back their real constraints (who's broke, who can't drive, who's running on two hours of sleep), and a group chat has no way to actually end . So we built the thing that does the deciding with you. What it does A host starts a session, types what the group is trying to decide ("where are we even going this weekend"), drops in a little context, and shares a link. Everyone who joins answers a short deck of questions — but here's the trick: the questions are generated by AI for that specific topic , and each one uses a different input style. Tap-to-pick cards for "all that apply," sliders for energy and budget, swipe cards for either/or calls. It never feels like a survey. Once everyone's in, lmk hits its money shot: the Results reveal . The AI reads every answer, finds where the group agrees and where it splits, and delivers a verdict — a top recommendation plus 4–6 concrete backups, each with reasoning that cites the group's own answers ("most of you wanted indoor, this fits the $$ range, and it works for the Saturday slot 5 of 6 picked"). If the group genuinely can't agree, that's not an error — lmk shows where you split, so the negotiation finally has a starting point. Save the verdict as a shareable card, drop it back in the chat, and you're done. From "let me know" to "let's go." How we built it Frontend: React 19 + TypeScript (strict) on Vite, styled with Tailwind v3 and shadcn/ui. React Router drives the SPA flow; html2canvas renders the shareable results card; sonner handles toasts. Deployed on Vercel's global CDN. Backend: A FastAPI (Python 3.13) service on Railway, with SQLAlchemy + Alembic over PostgreSQL. The AI engine uses the OpenAI API with structured outputs — Pydantic schemas passed as response_format so the model returns validated, typed JSON for both question and result generation. Real-time: Sessions are live. We use Server-Sent Events ( sse-starlette ) so when the host advances a session, every participant's screen transitions instantly — no polling. The AI pipeline is the part we're proudest of. Result generation is two-stage: first a summary pass, then a recommendation pass. Critically, the backend pre-computes the statistics (counts, averages, distributions per question type) and feeds them to the model, so recommendations cite real numbers instead of hallucinating them — we even validate that every recommendation references concrete data before we'll show it. Three retry attempts, strict schema validation, and a graceful fallback keep the experience solid on a live demo. Glue: slowapi rate limiting, CORS, input sanitization, and Pendo for product analytics on every key event. Challenges we ran into Making AI reasoning trustworthy, not generic. Early results read like "this fits the group's vibe" — useless. The fix was pre-computing real statistics on the backend and injecting them into the prompt, then validating that each recommendation cites a number. That single constraint is the difference between "cute" and "wow." Designing for honest disagreement. A group decision tool that only works when everyone agrees is a toy. Treating the no-consensus path as a first-class, intentional outcome ("here's where you split") took real design thought. Keeping it from feeling like a form. A list of questions is a survey. Getting the AI to pick the right mechanic per question — and validating those choices (multiselect must offer an escape option, swipe needs exactly two sides) — is what makes the deck feel alive. Live state across many clients. Coordinating ANSWERING → GENERATING → RESULTS across a whole group in real time, with three different ways to advance (full headcount, host skip, deadline), meant getting SSE and session state exactly right. Accomplishments that we're proud of The Results reveal — a genuinely screenshottable moment, with AI reasoning grounded in the group's actual answers. Evidence-backed AI — recommendations that quote real stats, enforced by validation, not vibes. A real-time, deployed, full-stack app — not a mockup. Live SSE, production hosting on Vercel + Railway, migrations, rate limiting, and analytics all wired up. A complete, on-brand voice — every screen, toast, and empty state written in a consistent, witty tone that makes the product feel like a finished thing. What we learned Constraining an LLM makes it smarter. Structured outputs, pre-computed stats, and validation gates produced dramatically better, more trustworthy results than a bigger prompt ever did. The edge case can be the feature. Designing the "no consensus" path turned our scariest failure mode into one of the most useful screens in the app. Pacing is a UX primitive. Varying the input mechanic per question changed how the whole experience feels — the same questions as a flat form would have been forgettable. Ship the reveal, polish the reveal. We spent our polish budget on the one moment the demo lives or dies on, and it paid off. What's next for LetMeKnow From categories to venues — plug in a places API so "coffee" becomes three real spots, with one tap to maps. Re-vote and tie-breakers — when the group splits, run a quick second round on just the contested axis instead of starting over. Persistent crews — save your group so recurring "what do we do tonight?" sessions remember your defaults. Native share + calendar drop — turn a verdict into a calendar invite the moment the group lands on it.
