## Body

Inspiration Every generative media demo ends at the same place: a video appears, everyone agrees it looks good, and the deck moves on. That last step is the one that doesn't survive contact with a regulated industry. A pharmaceutical ad cannot ship without its safety disclosure legible on screen. A bank's creative cannot imply a guaranteed return. A toy commercial has rules about what a child can be shown doing. Today a human watches the file and signs off in Slack, and the record of that approval is a message that can be edited, a Drive link that can be swapped, and a memory of who said yes. So the interesting problem in generative media isn't making the video. Models do that now. It's this: when the volume goes from ten assets a quarter to a thousand a week, the review step becomes the bottleneck, and the approval record becomes the liability. Notary is the compliance gate that generative pipelines never had. Every take is screened before it ships, and what clears is sealed somewhere nobody can revise it — not the reviewer, not the agency, not the account owner who holds the keys. What it does Notary sits between generation and publication and does three things. 1. It screens every take against a written brief. The brief is a list of criteria — "the safety disclosure is legible for at least three seconds", "the palette stays within brand tolerance", "no implied clinical claim". Notary runs each one and produces a verdict per criterion, not a single score. 2. It splits the verdict by how the answer was obtained. This is the design idea the whole product rests on, and it's the part I'd defend hardest: MEASURED criteria are computed from the pixels. Brand palette conformance is a CIE Lab ΔE calculation against the brand swatch. Disclosure duration is frame counting. These are reproducible — run them a thousand times, get the same number — and they carry no confidence score, because a measurement doesn't need one. REVIEWED criteria go to a vision model. "Is the logo present?" "Are there generation artifacts?" These come back with a confidence, because a judgement without one is a guess wearing a lab coat. Conflating those two is how AI review tools lose people's trust. A number computed from the file and an opinion from a model are different kinds of claim, and a compliance officer needs to know which one they're reading. So the interface never mixes them. 3. What passes gets sealed, and what's sealed can't be quietly changed. The certified asset, its manifest, the verdict, and an Ed25519 signature go to a Backblaze B2 bucket under Object Lock in COMPLIANCE mode . In that mode Backblaze itself refuses deletion for the retention period — I tested this against the live account, by version ID, with root credentials, and got AccessDenied . That's the property that makes the record worth something: I cannot alter it either. Uncertainty escalates rather than resolving itself. A blocking criterion the model isn't sure about produces ESCALATED , not a pass. An exhausted revision budget produces ESCALATED. The system is built so that the failure mode is "a human has to look at this", never "it shipped because the model shrugged". And every certificate is verifiable by a stranger. scripts/verify_certificate.py imports nothing from this project — standard library plus cryptography — because a provenance claim only checkable by the system that made it is not a provenance claim, it's a press release. How we built it Genblaze Genblaze isn't a wrapper around a model call here; the whole review is expressed as one of its pipelines. Pipeline(chain=True) runs generation and review as a single chained graph, so the manifest covers the entire lineage rather than just the render step. The Board's verdict is a manifest step. BoardReviewProvider subclasses SyncProvider and wraps the vision call, which means the compliance decision lands inside the Genblaze manifest as a first-class node — not as metadata bolted on afterwards. The manifest is the audit trail, so the verdict has to live inside it. ModerationHook (a constructor kwarg, not a decorator — see Challenges) gates the pipeline before spend. AgentLoop + CallableEvaluator drive the revise-and-retry cycle when a take fails a fixable criterion, with a hard budget so it can't loop forever. ObjectStorageSink writes renders straight to B2, so generated bytes never round-trip through the app. Mp4Handler for media handling. Trust Mode 2. Genblaze ships Trust Mode 1 (integrity) and lists Mode 2 (authenticated integrity) on its roadmap. Notary implements Mode 2 — Ed25519 over the canonical manifest hash, using the reserved Manifest.signature field, which is excluded from the canonical hash so signing doesn't invalidate what it signs. Integrity tells you the bytes didn't change. Authenticated integrity tells you who said so , and for a compliance record that's the whole point. Every SDK touchpoint goes through one file, genblaze_compat.py , so the version surface is a single reviewable boundary rather than imports scattered across thirty modules. Backblaze B2 Two buckets, deliberately different in character. Workbench — where Genblaze's sink writes renders and manifests. Versioned, with a lifecycle rule to expire rejected takes. Cheap, mutable, disposable. Vault — Object Lock, COMPLIANCE mode, versioned. This is the system of record. Certificates, manifests, verdicts, thumbnails and the certified asset land here and become immutable for the retention period. The app treats B2 as the source of truth, not as a file dump next to a database. On a cold boot with an empty local state, Notary rebuilds its entire library by listing the vault and rehydrating certificates from the objects themselves — which I tested by wiping local state and restarting. Presigned URLs serve private media without making the vault public. Providers and models Role Provider Model Text-to-video (primary) GMI Cloud Kling-Text2Video-V2.1-Master Image-to-video (chained) GMI Cloud Kling-Image2Video-V2.1-Master Video fallback GMI Cloud seedance-2-0-260128 Cross-provider fallback Luma via genblaze-luma Perceptual review (vision) Google gemini-2.0-flash The fallback is a different model family on purpose, so a Kling-side outage has somewhere to go. Review runs on a separate provider from generation because the Board looks at every take including the rejected ones, so its cost profile is completely different from the generator's. Stack FastAPI + Pydantic v2 on the backend, React + TypeScript + Vite + Framer Motion on the frontend, boto3 for the Object Lock retention APIs that Genblaze's sink doesn't expose, Pillow for the colour science, and a static ffmpeg wheel so frame extraction works on a fresh pip install with no admin rights. 71 tests. Dockerised, deployed on Render, CI on GitHub Actions. Challenges we ran into I nearly shipped a false claim about Object Lock. My first test deleted a certified object and then checked with head_object — the file was gone, so I wrote in my notes that Object Lock hadn't held. It had. On a versioned bucket a plain delete writes a delete marker ; the object is untouched underneath. Deleting by explicit version ID returned AccessDenied , which is what protection actually looks like. The mistake was mine and the fix was real: certificates now record asset_version_id , so a certificate points at an exact immutable version rather than "whatever is current at that key". The vault was write-only and every test passed. certificate_document() adds four keys for storage; the Certificate model is extra="forbid" . So every certificate serialised fine, uploaded fine, and threw a validation error on the way back in. Nothing caught it because nothing read a certificate back — the tests round-tripped the model, not the document . The README claimed "B2 is the system of record" while the system of record was unreadable. Fixed with certificate_from_document() and regression tests that specifically rehydrate from stored bytes. Six of my SDK assumptions were wrong, and I only found out by installing it. chat isn't in core; moderation is a constructor kwarg, not a decorator; signature is a str , not a structured object; ObjectStorageSink lives elsewhere than I assumed; the credential kwarg is named differently; retry_on_rate_limit doesn't exist. Every one had been written against the documentation and looked correct. ruff --fix silently disarmed the SDK boundary. genblaze_compat.py re-exports SDK names, so ruff flagged them F401 and deleted them. GENBLAZE_AVAILABLE stayed True while the names underneath were None — the worst kind of failure, one that reports success. Fixed with an explicit __all__ and five guard tests that assert the boundary is actually populated. Object Lock writes need Content-MD5 . S3 requires it whenever Object Lock parameters are present. The error message doesn't say so. Lifecycle rules on a versioned bucket return MalformedXML until you add an ExpiredObjectDeleteMarker rule at the same prefix. Live model IDs contradicted the docs. Three of my configured model IDs were wrong — one absent from the registry, one a case mismatch (IDs are case-sensitive), one returning a 404 that looked like an infrastructure fault. All three were taken from documentation. I re-verified every ID against /v1/models on the live account. And the one I couldn't engineer around: Backblaze's daily Class B transaction cap. Once hit, a nine-byte read is refused exactly as firmly as a six-megabyte one. No amount of caching or code cleverness gets past an account-level refusal — the correct response was to stop looking for a workaround and go raise the cap. Accomplishments that we're proud of The safety property is proven, not measured. decide() has a finite input space — criteria outcomes crossed with check kind, severity, confidence band, and remaining budget. So it isn't sampled, it's enumerated completely. Across 536,424 combinations , there is no input on which Notary certifies an asset whose blocking criterion failed or could not be resolved. A separate search confirms an exhausted revision budget never becomes an approval. Precision tells you a classifier is usually right. Exhaustive enumeration tells you there is no input on which the system approves something it shouldn't . For a compliance gate, the second is the property that matters, and it's the one you can actually promise a regulator. Everything was verified against live infrastructure, not documentation. Backblaze refused a version-ID delete with AccessDenied . 409,051 bytes re-hashed from B2 matched the certified digest. The Ed25519 signature verifies in a script that imports none of my code. A cold boot rebuilt the library from a bucket listing. Kling rendered 6.68 MB of real video. Provenance survives leaving the system. The manifest is embedded in the MP4 itself as an ISO-BMFF uuid box, and the manifest commits to the media hash excluding its own box — which is what resolves the circularity of a file containing a hash of itself. What we learned The technical lesson: the failures that matter are the ones that report success. The write-only vault, the ruff autofix, the Object Lock false alarm — none of these threw an error anywhere a test could see. Each one required going and looking at the real thing. I now trust "I ran it against the live account" and distrust "the documentation says", and that reordering changed how I build. The design lesson: legitimacy comes from what a system refuses to do. The features that make Notary credible are all refusals — it won't certify under uncertainty, it won't let an exhausted budget become a pass, it won't let me delete a sealed record. A review tool that can be overridden by the person being reviewed isn't a review tool. And the one that surprised me: an immutable record means your mistakes are immutable too.
